# Route53 Clone

An educational clone of the AWS Route 53 console — built with [Cloudscape](https://cloudscape.design/)
(the open-source design system AWS itself uses), a FastAPI backend, and SQLite. It recreates the
Route 53 user experience and core hosted-zone/DNS-record workflows; it does not implement real DNS
resolution. Not affiliated with, endorsed by, or connected to Amazon Web Services.

**Live demo:** [route67clone.vercel.app](https://route67clone.vercel.app) · backend API docs —
[atr0.pythonanywhere.com/docs](https://atr0.pythonanywhere.com/docs)

## 1. Setup

### Prerequisites

Python 3.11+, Node 20+, and either Docker (for `docker compose up`) or both runtimes installed
locally.

### Local development (two terminals, no Docker)

```bash
# Backend
cd backend
python -m venv .venv
.venv/Scripts/activate        # .venv\Scripts\Activate.ps1 on PowerShell, source .venv/bin/activate on macOS/Linux
pip install -r requirements.txt
cp .env.example .env          # set COOKIE_SECURE=false for local http://localhost
alembic upgrade head
python -m seed --reset        # loads ~15 zones / ~90 demo records
uvicorn app.main:app --reload --port 8000
```

```bash
# Frontend
cd frontend
npm install
cp .env.example .env.local    # BACKEND_ORIGIN=http://localhost:8000
npm run generate:api          # regenerates the typed client from the running backend's OpenAPI schema
npm run dev                   # http://localhost:3000
```

### Docker Compose (both halves)

```bash
docker compose up
```

Seeding is a separate, explicit step even under Compose — it never runs automatically on boot
(`python -m seed --reset` inside the backend container), so a fresh volume starts empty rather than
silently reseeding.

### Tests

```bash
cd backend && pytest              # 100+ tests: services, routers, validation grammars, cascade delete
cd frontend && npm run lint && npx tsc --noEmit && npm run build
```

## 2. Architecture overview

```
Browser
  │  same-origin (session cookie never third-party)
  ▼
Next.js App Router (frontend/)
  │  /api/* rewritten to the backend (next.config.ts) — proxy.ts guards auth client-side,
  │  the backend independently verifies the JWT on every request
  ▼
FastAPI (backend/)
  routers/      → HTTP layer: path/query binding, status codes
  services/     → domain rules (CNAME coexistence, quotas, cascade delete, BIND parse/serialize)
  repositories/ → query construction only, never commit — services own transactions
  models/       → SQLAlchemy ORM, five tables
  ▼
SQLite (WAL mode), PRAGMA foreign_keys=ON so ON DELETE CASCADE actually cascades
```

Four-layer backend (`routers → services → repositories → models`), feature-organised frontend
(`features/hosted-zones`, `features/records`, TanStack Query for all server state — no ad-hoc
`fetch` in components). The nine DNS record-type grammars are defined once, server-side
(`services/validation/grammars.py`), and served to the frontend via `GET /record-types` so the UI's
inline validation can never drift from the backend's real enforcement.

Full detail, including every design decision and the alternatives considered:

- [`docs/04-architecture.md`](./docs/04-architecture.md) — layering, structure, auth flow, state ownership
- [`docs/02-design-decisions.md`](./docs/02-design-decisions.md) — 20 numbered decisions with trade-offs

## 3. Database schema

Five tables, managed by Alembic migrations (never `create_all`):

| Table | Purpose |
|---|---|
| `users` | Seeded demo accounts only — no signup/reset flow |
| `hosted_zones` | One row per zone: name, type (Public/Private), description, generated nameservers |
| `record_sets` | One row per **record set** — `(hosted_zone_id, name, type, set_identifier)` unique, `is_required` protects the auto-created SOA/apex-NS pair |
| `record_values` | Child table, one row per value with an `ordinal` — three IPs on one hostname is three rows here, one row in `record_sets` |
| `hosted_zone_tags` | Key/value tags per zone |

Cascades: zone → record sets → values, and zone → tags, enforced with `ON DELETE CASCADE` *and* a
per-connection `PRAGMA foreign_keys = ON` (SQLite defaults this off — without it, cascades look like
they work while silently leaving orphans). A dedicated test (`test_cascade_delete.py`) proves this.

Full column/index/migration detail: [`docs/05-data-model.md`](./docs/05-data-model.md).

## 4. API overview

REST under `/v1`, OpenAPI schema auto-generated by FastAPI and served interactively at
**`/docs`** on the backend origin — the frontend's TypeScript client is generated from that same
schema (`npm run generate:api`), so a backend contract change becomes a compile error rather than a
silent drift.

| Area | Endpoints |
|---|---|
| Auth | `POST /auth/login`, `POST /auth/logout`, `GET /auth/me` — JWT in an httpOnly cookie |
| Hosted zones | Full CRUD under `/hosted-zones` — search/filter/sort/pagination server-side; `DELETE ?cascade=true` for the escape-hatch bulk delete |
| Records | Full CRUD under `/hosted-zones/{id}/records`, plus `/bulk-delete`; `GET /record-types` serves the nine validation grammars |
| Import / export | `GET /hosted-zones/{id}/export?format=bind\|json`, `POST /hosted-zones/{id}/import?dry_run=true` — atomic, preview-first |

Every list endpoint returns the same envelope (`{items, page, page_size, total, total_pages}`);
every error returns the same shape (`{"error": {"code", "message", "field"}}`) so the UI can branch
on `code` and attach messages to the right form field via `field`.

Full contract, request/response shapes, and error-code table:
[`docs/06-api-contract.md`](./docs/06-api-contract.md).

## 6. Known limitations

- BIND import's console UI (upload/paste + dry-run preview screen) isn't wired up yet — the parser,
  atomic commit, and API endpoint are fully built and tested (round-trip and bad-line-rejection both
  verified), but the "Import zone file" menu item is still disabled pending the frontend flow.
- No real DNS resolution anywhere — this app recreates the console experience, not a nameserver.
- The hosted demo is shared and stateful; there's no reset button. Run it locally for a clean,
  fully-seeded instance.

See [`docs/03-assumptions-mocked-data-notes.md`](./docs/03-assumptions-mocked-data-notes.md) for the
complete list of what's real, what's mocked, and why.
